# subagentOptimization

把 Codex 的模型选择、按需委派和子代理协作规则整理成一套可交给其它电脑 Codex 执行的提示词与模板。

如果这套方法对你有用，欢迎在公开仓库点一个 Star，方便以后回来。

[MIT 许可证](LICENSE) · 提示词交付 · Windows 优先 · macOS/Linux 待实测

## 它解决什么问题

模型路由配置很容易混入个人路径、服务地址和完整用户配置。直接复制到另一台电脑，可能丢失原有设置，也可能只复制了文件，实际模型和角色仍不可用。

本项目让目标 Codex 先检查技能与环境，再询问模型选择，最后备份、合并并分层验收。仓库提供可读的提示词、规则和角色，不提供 Python 安装脚本。

- **按任务决定是否委派**：小任务直接完成；输入齐备、边界互不冲突且有收益时才并行，通常 1–2 个，最多开放 4 个子代理。
- **模型由用户确认**：默认推荐混合模式及 DeepSeek 官方 `deepseek-flash`；没有第三方配置时采用原生 ChatGPT/GPT 模式。提供方、模型和推理强度都可自定义。
- **混合模式优先 DeepSeek**：普通子任务优先第三方常用档，复杂任务优先考虑第三方复杂档；GPT 按明确例外使用并说明理由。候选摘要缺失时先查完整目录及 schema，允许时优先验证显式派发，默认路径作为经验证的补充。
- **每个代理固定档位**：派发前选定模型和强度，同一代理执行中保持不变；上下文交接与故障接替分别管理。
- **角色按需使用**：调研、实现、独立检查三个职责可复用，不要求每项任务都经过三阶段流水线。
- **结果可以核对**：分别报告文件检查、配置加载、角色发现和真实派发，未测项明确保留。

最近整理已纳入 DeepSeek 子代理路由修复：保留第三方优先策略，将候选摘要、显式派发和默认派发分开核实。见[变更记录](CHANGELOG.md)和[路由排查](docs/路由排查.md)。

## 快速开始

### 1. 先安装 mattpocock/skills

按[上游安装说明](https://github.com/mattpocock/skills#installation-30-second-setup)选择适合当前 Codex 的方式。具体命令及兼容说明见[安装与验收](docs/安装与验收.md#先安装配套技能)。安装后必要时开启新会话。

**配置前必须核实** `handoff`、`grilling`、`domain-modeling`、`code-review`、`writing-for-agents` 的来源、可读入口及当前可用性。缺失或无法核实就停止，要求先修复安装；原生模式同样适用。

### 2. 在目标 Codex 中打开本仓库

把下面这段话交给它：

```text
请完整阅读并执行当前仓库的 prompts/配置入口.md。
先检查 mattpocock/skills 前置条件，缺失就要求我先安装并停止。
通过后先询问第三方配置是否完成，以及我选用哪个提供方和模型；默认推荐 DeepSeek 官方 deepseek-flash。
没有第三方配置时使用原生 ChatGPT/GPT 模式。主会话模型保持当前选择。
使用混合模式时优先使用我确认的第三方模型；GPT 派发须说明例外理由。
候选摘要缺少第三方时先按路由排查核实完整目录和 schema，不直接转用 GPT。
请先展示具体变更，按授权备份合并，并分别报告已测、未测和阻塞项。
```

无法直接读取仓库的会话，可复制[配置入口](prompts/配置入口.md)整段提示词，并提供它引用的模板与文档。缺少本机文件读写能力时只能获得配置计划。

### 3. 确认模型与安装范围

默认采用用户级全局配置，也提供项目级选项。目标 Codex 会询问第三方配置是否完成、是否使用第三方以及实际选用的模型。推荐值见[模型选择示例](config/模型选择示例.toml)，示例不能直接作为 Codex 的完整配置。

第三方预设为 `deepseek-flash/high` 和 `deepseek-flash/max`。原生模式及有理由的 GPT 例外预设为 `gpt-6-luna/medium`，复杂档为 `gpt-6-luna/low`。这些是本方案的任务适配预设，不是模型性能排名；不可用时由你确认替代。

hybrid 优先使用已确认的第三方模型，GPT 例外条件见[路由规则模板](config/AGENTS.model-routing.md#选择子代理)。工具候选摘要未包含第三方时，按[派发排查](docs/安装与验收.md#显式覆盖列表缺失时)核实完整目录与 schema，允许时优先验证显式派发，并按条件验证默认路径；不能仅凭摘要判定不能调用。

API Key 在目标电脑本地安全配置，**不要贴进聊天或写入仓库**。已有第三方配置不等于入口支持混合派发，须分别验证原生和第三方子代理。

### 4. 核对安装报告

报告应包含实际模式、修改文件、有效配置来源、仓库外备份及回滚方法，以及每项检查的结果。新会话尚未加载、模型未实际调用或平台未测试时，状态应为待验收或未测。

## 适用范围与限制

适合希望保留人工主模型选择、按需使用子代理，并让不同电脑遵循相同协作规则的 Codex 用户。它是配置工作流，不是请求级强制路由网关；运行效果取决于目标版本、账户权限、接入层及工具能力。

已有 Windows 接入层取得过 DeepSeek/high 文件工具及显式 high、max 派发的证据；不能据此声称开源预设的官网直连或全新机器已通过。具体能力边界见[兼容性说明](docs/兼容性.md)。

全新目标机安装、官网直连、完整混合流程、备份回滚、全部角色、max 工具能力、复杂任务质量和40%交接仍待验收。macOS/Linux 尚未实测，不承诺缓存命中、性能提升或成本下降。

## 参与维护

需求与问题通过本仓库 GitHub Issues 跟踪，工程技能约定见 [项目技能配置](docs/agents/issue-tracker.md)。公开文件采用[白名单](.gitignore)，诊断报告、逐轮测试记录和会话交接文档默认保存于仓库外；修复后只更新必要的用户说明。新增公开文件和提交前检查遵循[公开文件边界](AGENTS.md#公开文件边界)。
