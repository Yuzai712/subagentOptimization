# 安装与验收

本项目由目标 Codex 执行[配置入口](../prompts/配置入口.md)，无需运行本仓库安装脚本。配置阶段顺序、停止条件和授权边界以该入口为准。

## 先安装配套技能

先按 [mattpocock/skills 上游说明](https://github.com/mattpocock/skills#installation-30-second-setup)安装。2026-11-04 查阅的上游为 Codex 提供以下插件方式；先核实本机 CLI 的 `--help` 支持它们：

```sh
codex plugin marketplace add mattpocock/skills
codex plugin add mattpocock-skills@mattpocock
```

若当前版本不支持插件命令，可按上游可编辑文件方式使用 `npx skills@latest add mattpocock/skills`，交互选择 Codex、用户级范围及上游整套技能。两种安装方式选择一种，避免同名技能重复。上游建议每个业务项目运行一次 `setup-matt-pocock-skills`；它配置项目的 issue tracker 等约定，与本方案的技能安装检查分开，不能在安装路由时顺带创建用户未授权的外部资源。

安装后必要时开启新会话。配置入口至少核实 `handoff`、`grilling`、`domain-modeling`、`code-review`、`writing-for-agents` 五项的来源、可读入口和当前可用性。上游重命名或删除时报告不兼容并停止，取得用户明确决定后才能更新要求；不能根据近似名称自动通过。

缺失任一项或无法核实来源时，要求用户安装/修复并停止配置。此门槛适用于 native 和 hybrid。

## 配置位置与合并

- 用户级默认使用有效 `CODEX_HOME`，未设置时使用用户主目录下 `.codex`；不复制其它机器的用户目录。
- 项目级方式由用户选择，先核实目标版本的配置及角色路径与覆盖关系。项目级指令不能自动证明全局字段也会生效。
- 路由规则插入有效 AGENTS 文件的唯一标记段，三个角色来自 `config/agents/`；段外内容及无关配置保留。
- 角色发现、配置支持、工具字段由目标入口决定。[官方角色说明](https://learn.chatgpt.com/docs/agent-configuration/subagents)、[指令覆盖](https://learn.chatgpt.com/docs/agent-configuration/agents-md)、[配置字段](https://learn.chatgpt.com/docs/config-file/config-reference)用于核对；不能仅凭 CLI 版本推定桌面入口一致。

## 占位符清单

| 占位符 | 来源 |
| --- | --- |
| `{{MODE}}` | 已确认的 `native` 或 `hybrid` |
| `{{NATIVE_MODEL}}` | 目标入口可用且用户确认的原生模型 ID |
| `{{NATIVE_STANDARD_EFFORT}}` | 原生常用档，预设 `medium` |
| `{{NATIVE_COMPLEX_EFFORT}}` | 原生复杂档，预设 `low`；是方案约定而非性能排名 |
| `{{THIRD_PARTY_MODEL}}` | 已确认的真实派发标识，预设 `deepseek-flash` |
| `{{THIRD_PARTY_STANDARD_EFFORT}}` | 第三方常用档，预设 `high` |
| `{{THIRD_PARTY_COMPLEX_EFFORT}}` | 第三方复杂档，预设 `max` |

native 将第三方三个占位符填为“未启用”，仅注册原生候选。hybrid 只保留用户确认且实际支持的档位。最终规则不得残留占位符。

## 验收层次

| 层次 | 通过证据 | 不能据此宣称 |
| --- | --- | --- |
| 技能门槛 | 来源记录、可读入口、当前可用性 | 所有技能都已实际运行 |
| 静态文件 | TOML 解析、标记唯一、占位符清零、无关配置保留 | 客户端已加载 |
| 配置加载 | 目标入口支持的检查命令成功或启动日志证据 | 模型有权限、角色已发现 |
| 角色发现 | 三个角色被入口发现；或明确记录指令注入方式 | 三个角色都完成过任务 |
| 模型派发 | 原生/第三方分别有实际子代理调用证据 | 一次 API 响应能代表整个混合流程 |
| 工具执行 | 干净上下文子代理在私有临时目录写入、读回验证标记 | 正式业务场景全部通过 |
| 协作约束 | 实际任务中的并发、固定档位、释放、交接记录 | 规则文字构成硬拦截 |
| 缓存与成本 | 实际 usage 或账单证据 | 固定档位必然省钱或命中缓存 |

建议临时文件名为 `routing-smoke.txt`，验证标记为 `ROUTING_SMOKE_OK`。测试只接收最小无敏感任务包；第三方不接收完整聊天、凭据或业务资料。报告记录模型、档位、实际工具、返回结果和有效来源，不写原始请求历史。

## 显式覆盖列表缺失时

候选摘要缺失不等于完整目录缺失，也不等于派发失败。安装过程中出现此情况，完整执行[路由排查](路由排查.md)的证据链，再回到配置验收继续；不要直接改派 GPT。排查文档包含显式/默认两条路径、默认参数示意、实际模型元数据要求及不扩大重试预算的规则。

## 重复安装、失败与回滚

安装前在仓库外备份待改文件，并记录原先是否存在；在写入前确认原文件未被其它进程修改。重跑只更新规则标记段及本方案角色，不重复创建 TOML 表，不覆盖非本方案角色。

回滚按本次备份清单逐文件恢复：原先存在的恢复原始字节；本次新建且之后没有其它修改的文件才移除；若已有后续修改先比较再决定，不能直接恢复整目录。恢复后重新核对配置加载。私有报告保留备份位置与验证结果，不上传仓库。
