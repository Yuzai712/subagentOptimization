# 安装与验收

本项目由目标 Codex 执行[配置入口](../prompts/配置入口.md)，无需运行本仓库安装脚本。配置阶段顺序、停止条件和授权边界以该入口为准。

## 先安装配套技能

先按 [mattpocock/skills 上游说明](https://github.com/mattpocock/skills#installation-30-second-setup)选择一种安装方式。可复现基线如下；它确认来源和入口声明，不代表所有技能或目标机安装均已实测：

| 项目 | 固定基线及已核对范围 |
| --- | --- |
| 技能源码 | [4ae2317ddb22b046e26455e4f9c9b3aaaf62212d](https://github.com/mattpocock/skills/tree/4ae2317ddb22b046e26455e4f9c9b3aaaf62212d)：五项必需技能文件和插件登记存在 |
| 插件声明 | 该提交中的 `mattpocock-skills`，版本 `1.3.2`；marketplace 的 `source` 为同一提交的 `./` |
| 文件安装工具 | [skills 1.7.6](https://www.npmjs.com/package/skills/v/1.7.6)，要求 Node.js 22.20 或更高；已核对其[本地目录安装与复制选项](https://github.com/vercel-labs/skills/blob/7a5e920bead4b1039a6d6df5d7e1163b7b09423a/docs/commands.md#skills-add) |

先核实本机 CLI 的 `--help` 支持下列插件命令及 `--ref`，再按用户授权安装：

```sh
codex plugin marketplace add mattpocock/skills --ref 4ae2317ddb22b046e26455e4f9c9b3aaaf62212d
codex plugin add mattpocock-skills@mattpocock
```

若当前版本不支持插件命令或固定 ref，可使用文件方式。在**仓库外私有目录**执行以下命令；已有同名目录时先确认其来源，不能覆盖：

```sh
git clone --no-checkout https://github.com/mattpocock/skills.git mattpocock-skills-source
git -C mattpocock-skills-source checkout --detach 4ae2317ddb22b046e26455e4f9c9b3aaaf62212d
git -C mattpocock-skills-source rev-parse HEAD
```

前述命令成功、`rev-parse HEAD` 等于固定提交且工作树干净后，才执行安装：

```sh
npx --yes skills@1.7.6 add ./mattpocock-skills-source -a codex -g --copy
```

交互选择上游整套技能。`--copy` 避免安装结果依赖临时源码目录的符号链接。两种方式选择一种；已有同名 marketplace 或技能时先识别来源及版本，不重装覆盖。基线升级需要核对新提交、插件登记、五项入口和目标机可用性，再有意更新版本记录；不自动追随默认分支或 `latest`。其它已安装版本通过同样门槛后可保留，私有安装报告记录实际 commit/版本、安装方式和必要文件哈希，不将它冒充上述基线。

上游建议每个业务项目运行一次 `setup-matt-pocock-skills`；它配置项目的 issue tracker 等约定，与本方案的技能安装检查分开，不能在安装路由时顺带创建用户未授权的外部资源。

安装后必要时开启新会话。配置入口至少核实 `handoff`、`grilling`、`domain-modeling`、`code-review`、`writing-for-agents` 五项的来源、可读入口和当前可用性。上游重命名或删除时报告不兼容并停止，取得用户明确决定后才能更新要求；不能根据近似名称自动通过。

缺失任一项或无法核实来源时，要求用户安装/修复并停止配置。此门槛适用于 native 和 hybrid。

## 配置位置与合并

- 用户级默认使用有效 `CODEX_HOME`，未设置时使用用户主目录下 `.codex`；不复制其它机器的用户目录。
- 项目级方式由用户选择，先核实目标版本的配置及角色路径与覆盖关系。项目级指令不能自动证明全局字段也会生效。
- 路由规则插入有效 AGENTS 文件的唯一标记段，三个角色由 `config/agents/` 与公共规则装配；段外内容及无关配置保留。
- 角色发现、配置支持、工具字段由目标入口决定。[官方角色说明](https://learn.chatgpt.com/docs/agent-configuration/subagents)、[指令覆盖](https://learn.chatgpt.com/docs/agent-configuration/agents-md)、[配置字段](https://learn.chatgpt.com/docs/config-file/config-reference)用于核对；不能仅凭 CLI 版本推定桌面入口一致。

### 安装目标与共享范围

模板来源目录与业务项目根目录分别确认。选择项目级时，不默认安装到当前打开的分发仓库。写入前，私有来源矩阵覆盖用户级、业务项目级和有效 override 中的路由标记、三个同名角色，以及目标入口实际读取或拟修改的配置文件（如经核实支持的 `config.toml`）。逐项记录实际目标路径、存在状态、Git 跟踪/忽略状态、个人/团队用途、内容指纹、覆盖顺序及最终生效来源。只检查这些已知配置位置，不扫描整个用户目录。

配置文件还须逐字段记录现有 `agents` 默认模型与强度、并发上限、传输参数、当前角色注册来源，以及拟改字段的原值、计划值和最终生效来源；入口使用不同字段名时记录原字段到规范字段的映射。只记录非敏感值或环境变量名，不抄录凭据。未改但会覆盖计划值的配置也须纳入；字段支持或来源无法核实时记未知，写入前解决，不能仅列出准备新建的文件。

用户选择的是**个人安装**还是**团队共享配置**，须与差异一同明确。已跟踪文件会参与后续提交，`.gitignore` 对它无效；未跟踪且未忽略的文件也可能被提交。个人安装优先采用目标入口真正支持的本地方式，必要的 `.git/info/exclude` 变更也须列入事务，不能猜造私有指令文件名。若只有共享文件能生效，展示影响后让用户选择共享配置或改用用户级；不偷偷扩大忽略规则。团队共享内容须使用团队确认且适合公开的模型标识，不夹带个人路径、凭据或专用接入别名。

切换安装层级时，矩阵明确旧受管内容是保留、迁移还是清理及最终生效来源。仅清理本方案可证明拥有的片段/文件，清理进入同一事务；用户级配置可能服务其它项目，不因当前项目迁移就删除。存在符号链接或路径别名时，按解析后的真实目标去重并确认写入范围。

## 占位符清单

| 占位符 | 来源 |
| --- | --- |
| `{{MODE}}` | 已确认的 `native` 或 `hybrid` |
| `{{NATIVE_MODEL}}` | 目标入口可用且用户确认的原生模型 ID |
| `{{NATIVE_STANDARD_EFFORT}}` | 原生常用档，预设 `medium` |
| `{{NATIVE_COMPLEX_EFFORT}}` | 原生复杂档，预设 `low`；是方案约定而非性能排名 |
| `{{THIRD_PARTY_MODEL}}` | 已确认的真实派发标识，预设 `deepseek-flash` |
| `{{THIRD_PARTY_STANDARD_EFFORT}}` | 第三方常用档，预设 `high` |
| `{{THIRD_PARTY_COMPLEX_EFFORT}}` | 第三方复杂档，预设 `max` |

native 将第三方三个占位符填为“未启用”，仅注册原生候选。hybrid 只保留用户确认且实际支持的档位。最终规则不得残留占位符。

### 角色装配

三个源角色 TOML 的 `developer_instructions` 各含一次 `{{SUBAGENT_COMMON}}`，它不属于模型选择占位符。安装时先完成路由模型渲染，再核对 `<!-- codex-subagent-common:begin -->` 与 `<!-- codex-subagent-common:end -->` 各出现一次且顺序正确，提取两者之间的正文。

解析每份角色 TOML，在**解码后的指令字符串**中将唯一公共占位符替换为上述正文，再用 TOML 序列化器输出；不能把包含引号或反斜线的文本直接拼接到 TOML 源码。对结果重新解析，逐字核对职责部分与公共正文均保留，无残留占位符、无 `model`/`model_reasoning_effort` 字段。公共标记、角色占位符缺失或重复都在写入前停止。

安装产物是完整角色，不需要再次读取分发仓库；无具名角色入口时也只注入**装配后的** `developer_instructions`。源模板不能直接复制到有效 agents 目录。升级时重新装配并纳入事务，不在三个角色里分别手工修公共规则；该变化减少维护副本，不承诺减少运行 token。

## 验收层次

| 层次 | 通过证据 | 不能据此宣称 |
| --- | --- | --- |
| 技能门槛 | 来源记录、可读入口、当前可用性 | 所有技能都已实际运行 |
| 静态文件 | TOML 解析、标记唯一、路由及角色占位符清零、装配正文一致、无关配置保留 | 客户端已加载 |
| 配置加载 | 目标入口支持的检查命令成功或启动日志证据 | 模型有权限、角色已发现 |
| 角色发现 | 三个角色被入口发现；或明确记录指令注入方式 | 三个角色都完成过任务 |
| 模型派发 | 原生/第三方分别有实际子代理调用证据 | 一次 API 响应能代表整个混合流程 |
| 工具执行 | 干净上下文子代理在私有临时目录写入、读回验证标记 | 正式业务场景全部通过 |
| 协作约束 | 实际任务中的并发、固定档位、释放、交接记录 | 规则文字构成硬拦截 |
| 缓存与成本 | 实际 usage 或账单证据 | 固定档位必然省钱或命中缓存 |

### 隔离冒烟

主代理为每次入口/模型/档位/派发路径组合新建独立私有临时目录，生成不可复用的随机运行标识与标记，并先确认输出文件不存在。子代理在该目录创建 `routing-smoke.txt`，写入本次标记并读回；主代理独立读回，核对目录、精确内容及该次真实写入工具证据，同时核对运行模型与强度元数据。固定返回句、旧文件、其它路径的产物或代理自报均不能通过。

测试只接收最小无敏感任务包；第三方不接收完整聊天、凭据或业务资料。报告记录模型、档位、实际工具、返回结果和有效来源，不写原始请求历史。失败重试使用新目录与新标记并保留旧证据，不扩张既有重试预算。

### 任务交付覆盖

派发和验收遵循[规则模板](../config/AGENTS.model-routing.md#主代理派发与上下文职责)。任务包声明必需检查组、适用环境和通过条件；高风险契约由实现角色维护矩阵，检查角色独立补充反例。矩阵及回执保存在任务包指定的仓库外目录，不成为公开规格的副本。

| 回执字段 | 核对要求 |
| --- | --- |
| 产物版本 | 提交及 tree，或无 Git 产物的内容指纹；未提交改动另记内容指纹，不用 HEAD 代表未提交内容 |
| 检查组与覆盖 | 对应必需验收，注明离线、真实依赖或真实平台；不适用须有原因，变更必需组由主代理按授权处理 |
| 实际执行 | 命令、退出结果、通过/失败/跳过数及原因；非测试检查记录适用结果 |
| 证据复用 | 标明原证据、产物版本、相关输入/环境及本次变更影响；tree 相同不单独证明环境或输入相同 |
| 结论 | 必需组未运行、失败或跳过保持待验收；完成判定不能仅引用总通过数或 CI 状态 |

确定性检查由业务项目已有测试/CI 工具承接，覆盖缺口应通过退出状态或可核查回执体现；本仓库只交付通用契约，不增加业务测试执行器。静态模板检查通过不代表此门槛已在目标机强制生效。

### 等待能力验收

针对实际派发与等待入口，区分终态通知、定时唤醒、主动查询和主模型续回合。工具描述或退避守卫不足以证明无模型等待；仅在现有任务自然等待或另获授权的无敏感实验中验收，不为日常派发重复创建探针。

记录固定观察窗口内的入口版本、事件时间、查询与 sleep 次数、主模型回合数及终态处理延迟。使用完整事件/请求计数核对等待是否经过模型；只有通知到达或 token 字段缺失时，仍记调用开销未知。验证普通进度不重置退避、到期前不主动查询、完成/阻塞事件可立即处理；进程、日志和报告读取同样不能用于变相轮询。

有实际证据证明支持无需主模型续回合的事件/定时唤醒时才启用对应等待路径；不支持或不可观测时保留[公共等待约定](../config/AGENTS.model-routing.md#通讯等待与恢复)，报告能力缺口，不延长单次60秒阻塞上限。降低查询次数不等于降低模型调用或账单；安装本方案不自动安装等待适配器或修改宿主。

### 私有恢复清单

仅在跨上下文确需恢复执行者时，由主代理在仓库外受限目录维护必要工具代理标识与断点，按[生命周期规则](../config/AGENTS.model-routing.md#子代理生命周期)恢复。工具代理标识不含认证令牌或登录会话；不为补齐标识读取认证或完整聊天。访问者仅为获授权的主代理和恢复操作者，普通观测器及第三方子代理不读取；任务包只传其所需脱敏引用和断点。

创建前核对目录实际访问控制，清单采用同目录临时文件校验后安全替换，并协调单一写入者。记录保留截止条件；接收确认且不再需要恢复时按既有保留约定清理，未确认接收的交接材料先保留。清单不进入 Git、公开文档、普通报告或观测日志，观测数据只保留哈希/脱敏引用。模拟恢复使用合成标识；真实恢复需核实旧执行者是否仍写入，清单缺失不授权重复启动。

## 显式覆盖列表缺失时

候选摘要缺失不等于完整目录缺失，也不等于派发失败。安装过程中出现此情况，完整执行[路由排查](路由排查.md)的证据链，再回到配置验收继续；不要直接改派 GPT。排查文档包含显式/默认两条路径、默认参数示意、实际模型元数据要求及不扩大重试预算的规则。

## 重复安装、失败与回滚

重跑只更新规则标记段及本方案角色，不重复创建 TOML 表，不覆盖非本方案角色。结果字节相同的文件记为无变化并跳过，不用新备份覆盖旧事务。原有注释、编码和无关内容的保留仍需核对，不能只比较解析后的配置值。

### 安装事务与恢复

每次有实际变更的安装使用新的仓库外私有事务目录，并限制访问权限；完整配置备份可能包含敏感值，正文不进入聊天或公开材料。第一次写入前持久化不可变的 `plan.json`，逐文件记录：

- 已确认的真实目标与受管片段、原存在状态、原始字节备份、哈希及恢复所需权限元数据。
- 预期安装字节及哈希、预期存在状态（包括授权删除）、模板版本与角色装配来源。
- 操作顺序及初始状态。后续状态和实际写入后哈希写入独立的状态代际；初始为“已计划”，写前保存“将写入”，读回成功才记“已写入”；恢复另记“将恢复/已恢复/冲突”。

计划、A/B 字节快照及其校验值在首次业务写入前完整落盘、读回验证，随后保持不可变。状态按递增代际写到新的 `state-<代际>.json`，包含代际号、计划 SHA256、逐文件状态与实际哈希；每代另有校验值。先写私有临时文件并刷新、读回校验，再安全发布为该代文件，保留旧代；不能原地截断改写唯一清单。目标系统无法可靠发布或刷新时停止后续写入，不把仅在内存中的状态当持久化成功。

恢复先验证计划及所需 A/B 快照，再选计划哈希匹配且校验通过的最高状态代际，不按文件时间猜测。最新代损坏时保留损坏证据并退回旧代，用 A/B/C 核实未记账的实际写入；没有可用状态代但完整计划仍有效时，也可逐目标核实。计划或必要备份损坏、校验不符时停止受影响文件，保全当前内容与材料，不能猜测原字节或继续写入。

清单和备份先持久化，再逐文件执行。每个文件写前重新比较原状态；变化则暂停该文件，重读重算差异，超出已审阅范围时取得新的决定。待写内容在同目录临时文件中完整写入并校验，使用目标系统支持的原子替换或原子新建，再独立读回并更新清单。删除仅针对授权清单中的精确文件；禁止恢复或删除整个目录。

单文件原子替换仅防止半文件，不提供跨文件原子性，也不等于并发比较交换。存在已知并发写入者时先协调单一所有者或使用目标系统支持的互斥；无法保证安全写入、保留权限或持久化清单时停止受影响文件，不降为直接截断写入。失去执行上下文后，从清单与磁盘实际状态继续，不重放整个安装。

恢复时把**原版本 B、计划安装版本 A、当前版本 C**的存在状态和字节一并比较：

| 当前状态 | 动作 |
| --- | --- |
| `C = B` | 已是原状态，跳过；恢复可重复执行 |
| `C = A` | 原文件存在则恢复 B 的原始字节；原本不存在则仅移除本次新建文件；已授权删除则从备份重建 |
| 与 A、B 均不同 | 保存 C，执行三方比较，只撤销可明确归属的受管修改并保留外部编辑；同一内容冲突、范围不明或校验失败时停止该文件，保留材料待决定 |

即使清单停在“将写入”，也先用 A/B/C 判断文件是否已实际写入；不把尚未记录“已写入”当作没有副作用。恢复操作同样记录状态、校验及安全替换，完成后核对无关内容和配置加载。任何未解决冲突均报告“待验收/阻塞”，不宣称已完整恢复；私有报告给出事务位置和剩余精确操作。

## 可重复验收场景

以下是使用者可复用的验收契约，不是已执行记录。每项使用仓库外全新夹具、固定输入与预期结果，记录真实命令及产物；静态夹具或模拟执行器通过不能代替实际 Codex 安装。涉及真实配置的演练使用隔离环境，不对用户有效配置注入故障。

| 场景 | 输入或事件 | 通过条件 |
| --- | --- | --- |
| 首次安装 | 无受管内容，含现有其它配置 | 仅增加已确认项，主模型/认证/插件及段外内容不变 |
| 重复安装 | 同样选择执行第二次 | 产物逐字节不变，不增加表、注释或标记 |
| 无效模板 | 公共块或路由标记重复/缺失，角色占位符异常 | 写入前停止；有效配置零变更 |
| 角色装配 | native/hybrid 及含引号、反斜线的正文 | 三个角色均可解析，公共正文准确、占位符清零、无固定档位 |
| 同名冲突 | 他人同名角色或更高层 override | 展示来源和最终生效范围，未经决定不覆盖 |
| 共享目标 | 已跟踪 AGENTS 或未忽略配置 | 明确个人/团队用途，写入范围与审阅一致 |
| 已跟踪配置文件 | 项目配置文件已跟踪且含现有第三方默认值，另有用户级配置或 override | 来源矩阵列出配置路径、原值/拟改字段、Git 状态及最终生效来源；个人/团队共享影响已纳入具体差异和有效授权，保留无关配置 |
| 指纹复算 | 相同材料的对象键顺序不同，或目标能力/角色正文/有效默认值改变 | 按[指纹规范](路由排查.md#指纹材料与规范化)计算；前者相同，后者对应指纹不同；显式路径的 defaults 为不适用 |
| 旧版索引 | 版本 1 索引含 passed 记录，缺少原验证材料 | 保留原索引和全部记录，按[迁移规则](路由排查.md#旧版索引迁移)失效处理；只重算当前指纹不能恢复 passed，不自动追加探针 |
| 层级迁移 | 用户级与项目级各有旧安装 | 明确保留/迁移/清理，无意外删除其它项目所用全局配置 |
| 写前外部修改 | 计划后、写入前改变目标 | 检出差异，重算或停止，保留外部编辑 |
| 中断恢复 | 每个文件写前、替换后但日志更新前中断 | 根据 A/B/C 恢复，不依赖进程内状态；恢复再跑无变化 |
| 清单损坏 | 最新状态代截断，或计划/备份损坏 | 前者从完整旧代与 A/B/C 恢复；后者停止受影响文件，保留当前数据 |
| 写后外部修改 | 外部编辑段外或受管内容 | 段外编辑保留；受管冲突停止，不整文件盲目覆盖 |
| 新建与删除恢复 | 原不存在或计划授权删除 | 仅还原本次精确文件，不删除后续新内容 |
| 冒烟隔离 | 预置旧标记、路径错误或只有自报 | 主代理拒绝假阳性；仅本次随机标记加真实工具/模型证据通过 |
| 角色与协作 | 三角色分别派发、并行结束、交接或故障 | 实际职责、固定档位、关闭释放及相应预算有证据；未触发项记未测 |
| 契约覆盖 | 同一契约存在正常、拒绝、幂等及恢复入口 | 风险矩阵能定位入口、条件与证据；检查者独立补充反例，遗漏保留待验收 |
| 必需检查组 | 总测试通过但必需真实依赖组跳过，或复用证据的环境改变 | 不声明验收完成；区分新运行与复用，补足受影响组 |
| 资源冲突 | 两个依赖已满足的任务争用测试库重置权 | 仅资源持有者执行排他操作，其它无冲突工作可继续；不擅改需求依赖 |
| 等待唤醒 | 无状态变化、普通进度、终态事件及分段等待 | 按[等待能力验收](#等待能力验收)分别记录查询和模型回合；缺数据标未知，守卫放行不当能力通过 |
| 受限恢复 | 合成代理标识跨上下文恢复，含旧执行者仍活动与清单缺失 | 核对访问控制、断点及累计预算；不出现重复写入者，观测输出不含原始标识，未确认交接材料保留 |

修改入口、模板或恢复协议时运行受影响的场景；普通安装不自动执行全部故障与用量实验。静态检查固定覆盖本地链接/锚点、TOML、占位符、标记、源角色与装配产物一致性，以及公开边界。

## 性能对照基线

选择无敏感的固定任务集，至少覆盖一个小任务、两个可并行任务、一个有依赖的任务；固定输入版本与验收标准。在同一环境分别测“主代理直接完成”和“按当前规则委派”，记录主模型、固定子档、上下文策略、入口版本及缓存情况，每组至少三次并交替顺序。复杂档工具能力与任务质量单独记录，不把最小文本响应当质量通过。

每次记录端到端耗时、首次通过率、返工次数及同根因返工轮数，按[等待能力验收](#等待能力验收)另列主动查询、sleep、主模型回合数与终态处理延迟。记录主代理与所有子代理（含失败/接替）的输入、缓存、输出 token 和实际账单，汇总中位数及范围；注明统计边界，继承的累计计数不重复相加。

分别记录请求档位、工具是否接收、实际模型/强度元数据、业务交付结果与用量覆盖。缺少元数据、usage 或价格就记缺失，不按单个子代理用量推算总成本，不推定缓存命中；文档行数不替代实际输入 token。结果登记在仓库外[有效证据索引](路由排查.md#有效证据索引)，保持样本与失败记录可追溯。

这是单独、受授权用量约束的实验，不是安装必跑步骤。只有对应任务集的可比数据支持时才调整策略或陈述收益，不根据目录声明或一次成功修改用户模型偏好。
