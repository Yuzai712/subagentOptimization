# 第三方子代理路由排查

适用情况：混合模式仍频繁选择 GPT、工具摘要缺少第三方模型、实际执行档位与配置不一致。日常模型优先策略以[路由规则模板](../config/AGENTS.model-routing.md#选择子代理)为准，本文件集中维护安装与故障定位步骤。

## 先分清三类信息

| 信息 | 能证明什么 | 不能证明什么 |
| --- | --- | --- |
| 工具说明中的候选摘要 | 说明展示的部分候选 | 全部可选模型、第三方不可用 |
| schema 的硬枚举及入口约束 | 当前参数能否提交 | 后端权限和实际执行档位 |
| 完整有效目录及配置 | 已声明的模型、档位和默认设置 | 当前入口真实调用成功 |

参考的[上游说明生成函数](https://github.com/openai/codex/blob/main/codex-rs/core/src/tools/handlers/multi_agents_spec.rs)使用截断摘要，[候选配置源码](https://github.com/openai/codex/blob/main/codex-rs/core/src/agent/child_config.rs)定义摘要上限为五项。因此目标模型可能位于摘要之外，不能据此判定不可用。源码及入口会随版本变化，不要求所有版本采用相同数量或规则；目标版本须现场核实，硬枚举及明确禁止仍须遵守。

## 排查顺序

1. **确认选择原因。** 检查派发请求是否显式指定 GPT，角色是否固定模型，以及有效默认值是否为目标第三方档位。hybrid 普通子任务优先第三方，复杂任务优先考虑第三方复杂档；GPT 例外须说明理由，不因任务名是安装、编程或检查就自动选择 GPT。
2. **核对当前入口。** 分别记录工具摘要、schema、完整有效目录中的真实模型 ID 和支持档位。桌面当前会话、CLI 与新进程分别判断；后两者能发现模型，不能替代前者实际调用。
3. **验证显式路径。** schema 允许且无明确禁止时，使用已核实的真实 ID、显式模型与档位，派发一个最小无敏感任务。目录无法核实或硬枚举排除时报告限制，不猜参数。派发接受成功还不是完成证据，须继续核对实际结果。
4. **按条件验证默认路径。** 只读确认当前有效 agents 默认模型及强度与目标一致，角色没有覆盖；此时可在首次验收中省略模型、强度进行最小派发。日常使用省略参数的路径，须已有同一入口的真实完成和运行元数据证据。默认档不同或无法确认时，不用省略参数冒充目标档位，也不临时修改全局默认影响其它任务。
5. **核实实际运行。** 记录实际模型和强度的运行元数据、完成结果及工具执行证据。元数据只读取所需字段并脱敏，不拷贝整份运行数据库或聊天记录。仅有代理自报、配置、模型列表或普通 API 响应均不足以通过；拿不到元数据就标待验收。文件工具测试遵循[隔离冒烟](安装与验收.md#隔离冒烟)，每次使用独立目录和随机标记，由主代理独立核对。
6. **分别报告并复用。** 将显式派发、默认派发、工具执行分开记录，模型及档位分别记证据。high 成功不代表 max 工具能力也成功。一条路径失败而另一条仍有效时继续使用第三方；只有受支持路径均经核实不可用或存在其它明确例外时才考虑 GPT。共用接入层整体故障按同一故障处理，不为逐条尝试扩大鉴权、重试或接替预算。无新环境变化时复用有效证据，不反复跑探针。

## 默认路径参数示意

先通过上述默认值和角色覆盖检查。字段和角色名须按目标 schema 使用，无角色字段时采用规则允许的指令注入并注明。

```json
{
  "agent_type": "trellis-check",
  "fork_context": false,
  "message": "最小任务包示意：使用已确认的默认模型和强度，在主代理为本次分配的独立私有目录创建文件，写入本次随机标记，读回并报告。真实派发前须补全目录、标记及其余任务包字段。"
}
```

这里省略 `model` 和 `reasoning_effort`，不表示它们永远可省略。先确认默认档，任务完成后再核对真实元数据；不能把父代理继承规则或过期配置推测当作验证。任务包仍须包含目标、固定档位及来源、输入、边界、临时目录授权、验收与结束条件。

## 有效证据索引

索引默认保存于有效 `CODEX_HOME` 下的 `model-routing/evidence-index.json`；未设置 `CODEX_HOME` 时使用用户主目录下 `.codex`。这是目标机的私有状态，不是仓库文件或 Codex 原生配置字段。无法使用默认位置时，在已确认的私有目录保存，并把入口写入安装报告和后续任务包；索引缺失或不可读时记为缺证据，不把旧报告标题当通过。

JSON 顶层使用 `{"schema_version": 2, "records": []}`；按项目作用域、入口及派发组合分别记录，更新时保留其它记录。版本 2 固定下文指纹材料与字节算法；版本 1 按[迁移规则](#旧版索引迁移)处理。记录使用下列固定字段，不用同义字段名；未知值为 `null`，不能填成已验证值：

| 字段 | 类型与含义 |
| --- | --- |
| `record_id` | 字符串；按下文唯一键算法生成的 SHA256 小写十六进制 |
| `scope` | 对象：`kind` 为 `user` 或 `project`，`root` 为已解析真实目标根路径字符串；只存于私有索引 |
| `entrypoint`、`client_version` | 字符串或 `null`；入口标识区分当前桌面、CLI、新进程，不用版本号代替入口 |
| `provider` | 对象：`id`、`endpoint` 为字符串或 `null`；端点先移除认证信息，不能存含凭据的 URL |
| `identity` | 对象：`ref`、`revision` 为非敏感身份引用与变更标记字符串或 `null`；不保存密钥、Cookie或它们的哈希 |
| `model`、`effort` | 字符串；本条记录要验证的目标模型 ID 与档位，用于区分尚未执行的组合 |
| `actual_model`、`actual_effort` | 字符串或 `null`；从运行元数据取得，不能取代理自述；记为 passed 前必须与目标值一致 |
| `dispatch` | `explicit` 或 `default`；两条路径分别验收 |
| `role` | 对象：`name`、`source` 为字符串或 `null`；无具名角色时 name 使用 `none`，指令注入记录对应来源 |
| `fingerprints` | 对象，固定键 `tool_schema`、`config`、`catalog`、`defaults`、`role`；值为按下文规范计算的 SHA256 小写十六进制字符串、`null` 或字面量 `"not_applicable"`。`null` 表示未知；仅对确实不适用的来源使用 `"not_applicable"`，不能代替未知 |
| `checked_at`、`status`、`invalid_reason` | 时间为含时区 ISO 8601 字符串或 `null`；状态为 `passed`、`untested`、`failed`、`invalidated`；失效原因字符串或 `null` |
| `evidence` | 数组；每项固定 `kind`、`ref`、`sha256`，kind 为 `model_metadata`、`tool`、`artifact`、`cooperation` 或 `benchmark`，ref 为私有证据路径/可定位引用，sha256 为可取得的内容哈希或 `null` |

唯一键输入按固定顺序组成 JSON 数组：`[scope.kind, scope.root, entrypoint, provider.id, provider.endpoint, identity.ref, identity.revision, model, effort, dispatch, role.name]`；使用 UTF-8、无 BOM、不转义非 ASCII 字符、无多余空格的 JSON 字节计算 SHA256。路径由来源矩阵提供并沿用，版本与指纹变化更新同一记录并使旧证据失效；身份或执行组合改变则保留旧记录并生成新键。待验收记录可以含允许的 `null`，但不得复用为已通过；目标模型和档位始终保留，避免未知实际模型使不同待验收任务合并。

读取时校验版本、必需字段、类型、枚举和唯一键。重复 `record_id`、不兼容版本或损坏记录不能当成功使用，也不能静默丢弃后重写索引。更新同一键时先核实原记录未变化，保留新的有效证据引用；其它键保持原样。索引只保存下文材料的指纹，不转储完整配置、目录或角色正文；性能原始结果通过 `benchmark` 引用关联[性能对照](安装与验收.md#性能对照基线)。

### 指纹材料与规范化

每个哈希的输入固定为对象 `{"schema_version":2,"kind":键名,"material":下表材料}`，五个键分别计算，不哈希整份文件或索引。原字段到下表规范字段的映射及生效来源记入私有来源矩阵，后续沿用同一映射；入口换字段或新增会影响派发的字段时，先核对本规范是否覆盖，不能自行删减材料。不能完整取得材料或不能证明新增字段无关时，对应指纹为 `null`，不得复用为通过。

| 指纹键 | material 的固定内容 |
| --- | --- |
| `tool_schema` | 当前实际派发工具的 `{"name":工具名,"description":完整工具说明,"parameters":完整参数schema对象}`，包含硬枚举、角色选择、上下文选项及显式禁止说明；不从候选摘要重建 schema |
| `config` | 解析覆盖后的 `{"provider":{"id":提供方ID,"endpoint":去凭据端点,"protocol":实际API协议},"concurrency":并发上限,"transport":{"request_retries":请求重试次数,"stream_retries":流恢复次数,"stream_idle_timeout_ms":流空闲毫秒数},"role_binding":{"mode":角色加载方式,"name":角色名,"source":真实来源}}`；角色加载方式为 `named`、`injected` 或 `none`，无角色时 name 为 `none`、source 为 `"not_applicable"`；默认模型和强度单独进入 defaults |
| `catalog` | `{"model":目标模型ID,"efforts":支持档位字符串数组,"capabilities":该模型的完整目录对象}`；efforts 去重后按 UTF-16 排序；capabilities 只移除顶层 `display_name`、`description`、`icon` 三个展示键，其它原字段和值全部保留，不加入其它模型条目；同一目标有多条冲突声明时记未知 |
| `defaults` | 仅默认路径使用：`{"agent_model":有效子代理默认模型,"agent_effort":有效默认强度,"role_model":角色模型覆盖,"role_effort":角色强度覆盖,"resolved_model":合并后模型,"resolved_effort":合并后强度}`；已确认没有角色覆盖时两个 role 字段为 `"not_applicable"`；显式路径整个指纹为 `"not_applicable"` |
| `role` | 有角色时为 `{"mode":加载方式,"source":真实来源,"fields":角色内容}`；named 使用装配后实际加载 TOML 的完整解析对象，包含全部职责、公共正文及可能的覆盖字段；injected 的 fields 仅为 `{"developer_instructions":实际注入的完整角色指令}`，不包含任务包；确认无角色时整个指纹为 `"not_applicable"` |

材料使用解析后的值，配置注释、文件缩进和 TOML 引号形式不进入哈希；路径使用来源矩阵中已解析的真实路径原值。工具没有 description 时使用空字符串；其它字段只有已核实入口确实不支持或确实不存在时才填 `"not_applicable"`，不可观测不是不适用。未知按来源可观测性判断，完整 schema 或目录中的合法 JSON null 保留为源数据；材料含未知项时整个指纹为 `null`，不能哈希缺字段对象后假称完整。

先取上述非敏感字段，再执行 [RFC 8785 JCS](https://www.rfc-editor.org/rfc/rfc8785) 规范化：递归按 UTF-16 码元排序对象键；数组保留次序（仅 efforts 按上表先排序）；字符串保留 Unicode 原值，不做大小写、换行或 Unicode 归一化；数字与转义按 JCS 序列化；不输出额外空白、末尾换行或 BOM。对所得 UTF-8 字节计算 SHA256，输出 64 位小写十六进制。重复对象键、无效 Unicode、非有限数或无法无损映射到 JCS 输入的数据均记缺证据，不自行采用另一序列化算法。

材料、工具说明和目录对象进入哈希前必须确认无认证值；不读取认证文件，不把密钥、Cookie、认证头或其哈希混入材料。端点与记录的 provider.endpoint 使用同一去敏值：移除 URL 用户信息及经明确识别的认证查询参数，保留非认证参数及其原顺序；片段不参与请求，统一移除。不能确认路径或剩余参数无凭据时，端点及对应指纹记 `null`。不能安全取得其它非敏感材料时，对应指纹也使用 `null`。身份变化仍由非敏感 identity 引用及 revision 单独校验，不用密钥哈希替代。材料选择、去敏或规范化算法改变须升级 `schema_version`，不能在同版本下改算旧记录。

后续派发先比较当前可读的相关来源及身份引用；只有匹配且证据产物仍可核查时才复用。入口、身份、提供方/端点、模型、档位、工具 schema 或相关有效配置变化，令受影响的记录失效；角色修改使该角色的发现/执行证据失效，默认值改变使默认路径证据失效。变更无关文档不使模型派发证据失效。不设置定期探针或仅按时间重新鉴权。

记录更新采用私有临时文件校验后安全替换，保留已有记录；并发更新先协调，不能以最后写入覆盖他人证据。索引只负责查找与失效，引用仍需满足上文的实际元数据和完成证据要求。拿不到当前来源、身份或必要元数据时明确记待验收；索引本身不能把未测项变成通过。

### 旧版索引迁移

版本 1 没有统一指纹输入，不能仅改版本号或重算当前来源就保留 passed。经授权迁移时，先在私有目录完整备份原索引，再生成版本 2 副本，保留所有记录的唯一键、身份和证据引用，将旧指纹置 `null`、状态置 `invalidated`、原因记为 `fingerprint_contract_v2`；校验完整后按上述安全替换协议发布。未迁移、迁移失败或未知版本均保留原文件并记缺证据，不静默重建空索引。

恢复 passed 须能从原验证材料重建版本 2 指纹、与当前来源逐项匹配，并重新核对原完成及运行元数据证据；缺少原材料时只在既有授权与用量预算内重新验收受影响组合。迁移本身不自动追加探针，不修改实际模型、强度或认证配置。

## 官网预设与已有接入层

公开版默认推荐 DeepSeek 官网 `deepseek-flash`，已有接入层可能使用不同的真实派发 ID。目标配置使用用户确认的 ID，不复制原机专用别名。接入层 high/max 的成功证据不代表官网直连、自定义提供方或其它电脑也通过；这些都按[安装验收](安装与验收.md#验收层次)分别核对。

## 何时考虑钩子

本方案默认不安装钩子。候选摘要截断属于说明问题，钩子不能增加模型接入能力。只有用户明确需要强制拦截、且真实入口支持时才另行设计，并在安装前说明匹配范围、例外、失败行为和回滚；不能把已明确选择的 GPT 静默改写为第三方。
