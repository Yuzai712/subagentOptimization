# Codex 配置入口提示词

将下面整段提示词交给已打开本仓库的目标 Codex。网页会话须先具备仓库文件读取及本机配置能力；仅能阅读网页时只能出具计划，不宣称安装成功。

```text
请根据当前仓库，为这台电脑配置 Codex 模型路由与按需子代理协作。所有说明使用简体中文。

目标：复刻本仓库的协作行为和三个职责角色，依据这台电脑的真实模型、入口与授权合并配置。仓库不提供 Python 安装脚本，由你使用当前环境允许的工具实施。主会话模型保持用户当前选择。

按以下顺序执行，前一步通过后才进入下一步。

1. 技能门槛（配置写入前的硬条件）
先只读检查 mattpocock/skills 是否已安装。至少核实 handoff、grilling、domain-modeling、code-review、writing-for-agents 五项：上游来源或插件/安装锁记录可追溯、SKILL.md 可读、当前会话有可用调用入口。文件存在不能单独证明已加载；插件名称、目录名也不能单独证明来源。
若任一项缺失、来源无法核实或当前会话无法使用，列出具体缺项，要求用户按 docs/安装与验收.md 先安装/修复并在必要时开启新会话，然后停止。此时不得修改 config.toml、AGENTS.md、角色或模型目录，也不得自动代装后跳过复查。禁止把“可降级运行”当作通过技能门槛。
本仓库不捆绑上游技能。只读取任务必需技能，不预载整个技能库。

2. 识别目标环境与询问模型
只读识别操作系统、Codex 版本、CLI/桌面/IDE 入口、当前派发工具实际字段，以及用户级/项目级配置覆盖关系。CODEX_HOME 已设置时使用它，否则使用用户主目录下 .codex。核实 AGENTS.override.md 与同名角色覆盖来源；不能把本仓库自己的 AGENTS.md 当成已经安装的用户级规则。
默认用户级全局配置，同时允许用户选择项目级；先确认范围。分别记录模板来源目录和实际业务项目根目录，不能把当前打开的分发仓库默认当成安装目标。按 docs/安装与验收.md 的“安装目标与共享范围”建立来源矩阵，覆盖路由、角色和实际读取或拟修改的配置文件，列出 Git 状态、个人/团队用途、现有 agents 默认值及拟改字段、覆盖顺序和最终生效来源；项目级路径和支持字段须根据目标版本核实。个人安装不能仅因文件被忽略就认定不会发布；已跟踪文件的共享影响须纳入用户确认的具体差异。
询问用户：“第三方模型配置是否已经完成，且愿意在本方案中使用？若使用，请确认提供方、实际模型 ID 和可用推理强度。默认推荐 DeepSeek 官方 deepseek-flash。” 不要求用户把 API Key 贴进聊天。
没有第三方配置或用户不使用第三方时，选 native，使用目标用户可用的原生 ChatGPT/GPT 模型。用户选择先完成第三方配置时暂停混合配置，提供官方说明，由用户本地完成后复查；不能为了接通第三方而改变主会话模型。
已有第三方配置且用户确认使用时，hybrid 为目标模式。核实原生和第三方是否均能从当前入口派发；如不能跨提供方调用，说明缺口，让用户选择 native 或先补齐接入。只更换模型名或顶层 model_provider 不能证明混合可用。不得静默把全部 GPT 请求改发第三方。
默认原生候选 gpt-6-luna/medium，原生复杂档 gpt-6-luna/low（界面 Light）；第三方推荐 deepseek-flash/high、deepseek-flash/max。hybrid 在适合委派的任务中优先第三方，复杂任务优先考虑第三方复杂档；GPT 只按规则模板中的例外条件使用，派发前说明理由。该策略不代表实测性能排名或固定流量比例。目标账户/入口不支持某模型或强度时，给出查到的可用项，让用户确认替代，不能猜造或静默改档。第三方自定义后，也须确认常用档和复杂档；不支持两档时由用户确认合并或缩减候选。
完成条件：用户确认实际目标、安装范围及共享用途、native/hybrid、原生候选以及启用时的第三方提供方/模型/档位；记录不含凭据的选择摘要。来源矩阵中的旧安装及 override 已明确保留、迁移或清理，清理同样纳入变更与回滚范围。

3. 读取模板，形成具体变更
完整阅读 config/AGENTS.model-routing.md、config/agents/ 下三份 trellis TOML、docs/安装与验收.md、docs/模型与提供方.md。遵循已可用的 writing-for-agents；需要新增决定或统一术语时按 domain-modeling 处理，不为安装强制启动需求访谈或多代理流水线。
渲染路由模板全部占位符，核对 config/模型选择示例.toml 的字段含义。native 模式将三个 THIRD_PARTY 占位符渲染为“未启用”，不注册第三方候选；hybrid 使用用户确认的真实可派发标识与强度。示例文件仅供理解，不是完整 Codex 配置，也不能直接复制为 config.toml。
按 docs/安装与验收.md 的“角色装配”从渲染后的路由模板提取唯一公共块，在解析后的三个角色 developer_instructions 中替换 SUBAGENT_COMMON 占位符，再序列化为 TOML。源角色是装配模板，不能直接复制安装；完整产物不依赖模板仓库继续存在，且不得残留任何占位符。渲染失败在写入前停止。
显示脱敏变更清单与可审阅差异，包括规则标记段、三个角色、当前入口支持的 agents 默认字段、并发上限4、支持的传输参数1/1/300000。hybrid 的 agents 默认模型与强度设为用户确认的第三方常用档，native 设为原生常用档；角色保持不绑定模型。入口不支持的配置字段不写入，明确其运行限制；行为规则与运行时硬约束分别说明。
保留主模型、认证、现有提供方端点、MCP、插件、授权、其它角色及标记段外指令。对同名角色、重复/损坏标记、AGENTS.override.md 覆盖或配置冲突先说明；新冲突须有用户决定，不能静默覆盖。不要为采用本方案关闭沙箱或修改授权策略。
用户已有安装授权且差异在范围内时继续；缺少写入授权时，先展示这份具体差异再取得授权。

4. 备份、验证、合并
执行 docs/安装与验收.md 的“安装事务与恢复”协议。每次实际变更新建仓库外私有事务目录；首次写入前持久化原始字节/存在状态、计划字节/哈希、受管范围、备份及逐文件状态。新内容先在临时目录进行 TOML 语法与目标版本支持字段检查。目标 CLI 支持严格配置检查时使用其实际参数，不能猜命令。完整配置输出只在私有临时文件中检查，不能转储进仓库或聊天。
合并到实际生效配置，AGENTS.md 路由段使用唯一标记：
<!-- codex-model-routing:begin -->
（渲染后的规则全文）
<!-- codex-model-routing:end -->
若已存在完整标记只更新该段；重复或不成对先停止。写入装配完成的角色时保留非本方案角色；角色文件只定义职责，不写 model 或 model_reasoning_effort。
优先使用目标版本原生支持的角色发现/注册方式；无具名角色字段时使用规则明确允许的“角色指令注入”，记录这种兼容方式，不冒充具名角色加载成功。
无差异文件跳过。合并前重新核对文件是否被其它工具修改；发生变化则重读重算差异，不覆盖。逐文件记录即将写入状态，经同目录临时文件校验后使用目标系统支持的原子替换，再读回记录实际哈希。无法安全替换或有并发写入风险时停止受影响文件；单文件原子替换不等于多文件原子事务。失败或中断恢复按原版本、计划安装版本和当前版本比较，只撤销已确认的本次修改；冲突保全材料后报告，不盲目恢复原备份。重复执行结果应稳定，不重复表、规则段和注释。
密钥只通过用户本机已有安全配置或环境变量引用；不读取认证文件内容，不导出 Cookie，不把真实密钥放入项目、日志、任务包或聊天。认证由用户控制。

5. 验收与交付
按 docs/安装与验收.md 区分静态检查、配置加载、角色发现、真实模型请求、子代理工具调用及协作行为。请求模型目录只能证明声明，不能证明权限；API 单次响应不能证明子代理成功。
分别记录当前工具的候选摘要、schema 硬枚举、完整有效目录、显式派发与默认派发结果。摘要可能只展示前几项，未包含第三方时不直接判定不可用：核实完整目录中的真实模型 ID 及档位，schema 允许且无明确禁止时，用最小无敏感任务验证显式派发；不绕过硬枚举或猜造模型名。也可只读核实有效默认模型、强度和角色覆盖，在默认档一致时省略 model 与 reasoning_effort 验证默认派发。两条路径均须用运行元数据确认实际模型和强度，并核对完成结果。验证失败、证据不足或默认档不符时明确报告，不冒称目标档位成功，不默默改派 GPT。CLI、新进程与当前桌面入口分别报告，不能互相替代。
真实请求使用最小无敏感任务：由主代理为每次入口/档位/路径验证分配独立临时目录和随机标记，子代理创建文件并读回后，主代理独立核对产物和本次工具证据；详见 docs/安装与验收.md 的“隔离冒烟”。使用无完整历史的干净上下文，记录请求模型、档位、入口、工具执行结果、产物和限制；不向第三方发送主会话历史。真实请求会产生实际用量，仅在用户授权范围内执行，不为测试重复探测。
native 至少验证一次原生子代理；hybrid 分别验证原生和第三方子代理。当前会话需重开才加载时先标待验证，不用旧会话声称新配置生效；不要自动关闭用户已登录窗口。角色分别验证发现和实际使用。若用量、故障、缓存或平台没有运行证据，一律标未测，不由规则文件推定成功。
将验证结果登记到 docs/路由排查.md 的“有效证据索引”，按该文档的指纹材料、规范化及旧版迁移规则处理，索引留在仓库外并在私有安装报告中给出位置。日常任务复用相符且未失效的证据；允许时优先显式指定，默认路径按规则模板条件使用。模型、复杂档或入口变化只重验受影响部分，不能把常用档成功扩展为复杂档也成功。安装验收中的原生对照调用属于明确的 GPT 例外，应标明用途。
钩子仅在用户确有强制拦截需求且目标入口已验证支持时考虑；先展示匹配范围、例外、失败行为及回滚方法，不自动安装。钩子不能新增模型能力，也不应把已明确选择的 GPT 静默重写为第三方。仅修改规则即可解决时不增加钩子依赖。
配置加载或关键真实调用失败时报告“待验收/阻塞”，按用户选择回滚或保留待修复状态；不能自动改模型掩盖失败。技能门槛失败始终停止，第三方未配置则采用原生，两者不能混为一种降级。
最终给出：已应用/待验收/阻塞；目标及共享范围、模式与候选摘要；修改文件及有效来源；事务状态、备份与精确回滚方式；证据索引；实际命令和关键输出（脱敏）；各平台和各验证层的已测/未测；剩余操作。按 docs/安装与验收.md 的场景表报告覆盖情况，未执行的异常场景不算通过。性能对照是单独实验，不在每次安装中自动追加用量；没有完整用量时不声称节省成本。私有安装报告和备份均留在仓库外。

完成后停止，不自动创建或推送 GitHub 仓库，不安装无关插件或修改其它应用。
```
